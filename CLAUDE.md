# Readthrough (repo: BetaReader) — notes for Claude

AI beta reader for authors. Next.js 16 App Router + Prisma 7/Postgres + Auth.js + Anthropic SDK. See README.md for the architecture.

- Run `npm test` and `npm run typecheck` before committing.
- The reader pipeline lives in `src/lib/reader/pipeline.ts`. Chapters are read strictly in order; each read returns a `memory` that is the only context passed to the next chapter. Don't give the reader access to later chapters.
- Model output is structured via structured outputs (`output_config.format`, see `callStructured` in `src/lib/reader/anthropic.ts`); `toStructuredSchema` strips unsupported JSON Schema keywords. If you change a schema in `src/lib/reader/schemas.ts`, update both the zod schema and the JSON `input_schema` beside it. Forced `tool_choice` is not supported by current models.
- Feedback tone rules live in `CORE_PRINCIPLES` in `src/lib/reader/prompts.ts`: honest, specific, quote exact passages, fixes not just flags.
- Every query of user data must be scoped to the signed-in user (`requireUser()` / `currentUserId()`).
- Model is configured with `ANTHROPIC_MODEL` (default `claude-sonnet-5-5`).
- Prisma 7: the client is generated into `src/generated/prisma` (gitignored; `npm install` runs `prisma generate`). Import types and the client from `@/generated/prisma/client`, never `@prisma/client`. The DB connection goes through `@prisma/adapter-pg` in `src/lib/db.ts`.
- The dev email login only exists when `AUTH_DEV_LOGIN=true` and `NODE_ENV` is not production (`next dev`), by design.
- Editor chat is switched off for v1 via `FEATURES.editorChat` in `src/lib/features.ts` (the user wants v1 focused on the read itself). Keep its code working, but don't surface it unless asked.
- Chapters: `Chapter.doc` is the TipTap/ProseMirror JSON the editor saves; `Chapter.content` is the plain text derived from it (`docToPlain`) that the AI reads and notes anchor to. Always write both together (see `saveChapter`). `contentUpdatedAt` vs `ChapterReview.readAt` decides whether notes are out of date (`isReviewStale`).
- Editor allows only paragraphs, hard breaks, scene breaks (horizontalRule), bold and italic; `sanitizeDoc` enforces this server-side.
- Reader journey: `ReaderThread` rows are created/resolved inside `readChapter` (pipeline.ts). A re-read of chapter N first deletes threads raised in N and reopens ones resolved in N. The author's intent and previous issues are put AFTER the chapter text in the prompt so they can't bias the reaction.
- Grammar & style and character discovery use `ANTHROPIC_LINE_MODEL` (default claude-haiku-5-5); reading and character chat use `ANTHROPIC_MODEL`.
- Character chat: system prompt in `src/lib/reader/characters.ts`; invented details are wrapped in ⟦ ⟧ and rendered by `Markdown.tsx` as highlights.
- Re-import: `reimportDraft` (src/app/reimportActions.ts) previews then applies a revised upload using `matchChapters` (src/lib/manuscript/match.ts). Store imported text via `canonicalText` and set `doc` from it, so it matches what the editor would save. Kept chapters are parked on negative indexes before renumbering to avoid the (manuscriptId, index) unique clash. `readManuscript(id, { rereadChanged: true })` re-reads only stale or unread chapters.
- Continuity: `StoryFact` rows are written per chapter in `readChapter` and deleted when that chapter is re-read (like threads). The reader only ever gets facts from EARLIER chapters (capped at MAX_BIBLE_FACTS). Contradictions are saved as ISSUE notes with category "continuity".
- Pitch kit: `writePitchKit` (src/lib/reader/pitch.ts) uses summaries, final memory and the book report, not the full manuscript. Needs a finished read.
- Billing & limits (src/lib/billing): every AI call MUST carry a `meter` (callStructured requires it) or, for streams, `holdCost()` before and `settleCost()` after with `streamUsageTracker`. Work that consumes an allowance must `reserve()` BEFORE calling the AI and `release()` on failure. Throw/propagate `LimitError` unchanged so the UI can show the reason. Plan → subscription mapping is by Stripe price id env vars (src/lib/billing/stripe.ts). Pricing figures in `src/lib/billing/cost.ts` must match platform.claude.com pricing.
- Brand: the product name is Readthrough; use `BRAND` from src/lib/brand.ts, never hard-code it. Red (`pen` colour) is reserved for "marks" (logo bar, active nav, flagged items), not decoration. Public pages use `PublicHeader`/`PublicFooter`.
- Characters: pronouns (and the profile fields) are canon. `castBlock(castWithPronouns(id))` (src/lib/reader/cast.ts) adds names + pronouns ONLY to every reader/report/pitch/editor/character prompt; never add plot details there (the reader reads in order). Discovery fills blank profile fields from the text and never overwrites the author's. Pictures live in `CharacterImage` (bytes, never selected with Character), are resized in the browser, sniffed server-side (JPEG/PNG/WebP only), and served auth-checked from /api/characters/[cid]/image.
- v1 is "reads, never writes": no prompt may ask for example rewrites or replacement prose (see CORE_PRINCIPLES). The pitch kit writes prose, so it's behind `FEATURES.pitchKit` (off).
- Long AI work goes through the job queue (`scheduleJob` in src/lib/jobs/schedule.ts), never `after()` directly. Handlers live in src/lib/jobs/handlers.ts and must be safe to run twice; reservations travel as JSON (`toJsonReservation`). The worker runs with `tsx --conditions=react-server` so `server-only` imports work.
- Drop-off map and draft comparison logic are pure (src/lib/reader/dropoff.ts, drafts.ts) with tests. Snapshots are taken with `keepSnapshot` before a re-import applies and before a fresh read wipes the old one; chapters are matched by id.
- Imports go through `importFile`/`fromText` (src/lib/manuscript/import.ts): heading structure first (structure.ts, built for Dabble exports), then the text splitter.
- Free sample reads (src/lib/trialRead.ts) have no user: `Meter.userId` is null, `holdCost` applies the trial budget instead of a user's, and `AiUsage.userId` is null. Never show a TrialRead's content anywhere but its own /try/[id] page.
- Promises about manuscripts (no training, vendor, deletion) live in src/lib/trust.ts and the /privacy page; change them together.
